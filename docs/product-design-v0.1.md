# singbox TUI 产品设计 v0.1

日期：2026-09-13。状态：供评审的产品设计草案；不是已实现功能清单。

## 1. 产品承诺

在 macOS 或 Linux 的终端内，粘贴订阅链接，选择节点并连接；之后在同一个界面管理订阅、分流和网络状态。普通用户无需手写 sing-box JSON，也无需知道订阅采用什么编码。

临时项目名为 singbox TUI。正式名称后定，避免暗示这是 sing-box 官方客户端。

已确认：Mac 本机 + Linux 本机及 SSH；界面默认英文，支持中文切换。以下讨论说明采用中文，主要界面线框采用英文。界面翻译覆盖帮助、空状态和错误信息，用户节点名称保留原文。

主要用户是经常使用终端、但不熟悉代理核心配置的人。高级用户可以查看生成配置、调整规则、导入自有完整配置。首版以本机 sing-box 为管理对象；通过 SSH 启动 TUI 时，“本机”指 SSH 远端机器，不会自动让用户的 Mac 走远端代理。

## 2. 三种产品路线与选择

| 路线 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 以单屏向导为主 | 首次使用简单 | 日常节点管理与诊断容易变成层层菜单 | 用于首次使用和添加订阅 |
| 以多面板工作台为主 | 高频操作快，可边选边看详情 | 信息密度容易过高 | 采用，但每页只突出当前任务 |
| 以配置树和 JSON 编辑器为主 | 全功能可表达 | 要求用户先懂 sing-box | 保留为高级入口，不作为默认首页 |

推荐：简短首次向导 + 日常工作台 + 按需展开的配置辅助。不是让用户在“新手/专家模式”间切换；基础操作始终可见，细节逐层展开。

## 4. 页面结构

全局顶部显示：正在管理的主机、连接状态、当前出口、接管方式、待应用变更。后台任务只占一条短状态提示。

| 页面 | 回答用户的问题 | 主操作 |
|---|---|---|
| 总览 | 现在连通了吗？流量走哪里？ | 连接/断开、选择出口、诊断 |
| 节点 | 用哪个节点？ | 搜索、测试延迟、收藏、设为出口 |
| 订阅 | 节点从哪里来，更新了吗？ | 添加、更新、查看更新差异 |
| 配置 | 哪些流量走代理？ | 设置接管方式、DNS、规则、配置档案 |
| 活动 | 哪个连接有问题？ | 连接/日志子页、过滤、详情 |

主题、语言、启动行为、核心版本和后台服务放在设置菜单。高级 API、路径和原始 JSON 不占顶层导航。

总览是默认入口；节点页是主要高频工作区。记住上次页面、筛选和滚动位置，但重新进入时连接状态始终可见。

## 5. 首次使用：一个可以走通的任务

1. **检查环境。** 显示系统和 sing-box 检测结果。已有核心可直接使用；缺少核心时提供安装动作与清楚进度。首次下载失败允许选择本地二进制。检测过程不接管网络。
2. **添加订阅。** 仅要求一个链接；名称可自动建议后修改。也支持节点分享链接和本地文件。直接接受终端粘贴，不依赖远端剪贴板命令。
3. **查看结果。** 例如“已导入 48 个节点 · 2 个不支持”。可看原因。若为完整 sing-box 配置，默认提供“提取节点并使用本客户端设置”；另有明确的“作为自有配置导入”。
4. **选择接管范围。** macOS/Linux 本机通常建议“整个系统（TUN）”；SSH 场景建议先使用“仅代理端口”。界面解释应用覆盖和需要的授权。用户可以更改建议。
5. **准备连接。** 显示所选出口、分流摘要与需要应用的系统变更，执行校验。连接后分别显示“核心已运行”和“连通性测试结果”，不能仅凭 PID 宣称网络可用。

默认从延迟测试中选择一个可用节点，允许手动选择。测试 URL 可配置；测试失败不直接判定节点绝对不可用。无节点成功时显示“未验证连通”，允许用户看详情或重试。

推荐分流预设以中文用户需求为假设：局域网直连 + 中国大陆常见流量直连 + 其他代理；同时提供全部代理与自定义。地区规则应使用可验证来源的规则集，本地缓存就绪后才应用，不把 DNS/TUN 大量参数放进首屏。

## 7. 配置辅助：用意图编辑

核心问题是“我要改变什么行为”。例如用户输入：

> 网站 example.com 及其子域名 → 通过日本节点组访问

界面先给出“网站/域名”“应用或进程”“IP/网段”等条件，再选择直连、拒绝或出口组。平台不支持的条件需显示原因；macOS/Linux 的进程识别等能力须实际验证后启用。

配置页包含：

- 接管方式：整个系统 / 系统代理（可用时）/ 仅代理端口。
- 分流：预设选择 + 用户规则；规则有明确的先后顺序，可移动和查看解释。
- DNS：推荐预设 + 高级展开，描述行为而不强迫用户理解底层字段。
- 出口组：手动选择或自动选择；成员来自订阅、收藏或手工节点。
- 配置档案：保存如“日常”“工作”的行为设置。

辅助解释示例：“example.com 当前会匹配第 3 条规则，使用日本组。”只有规则和上下文足以确定时才显示确定结论；不能静态判断的条件（进程、实际解析 IP 等）显示缺失信息。完整流量路径解释器属于后续能力，不伪装成首版已可确定一切。

保存形成草稿。点击“应用”时显示人类可读的变化，如“新增 1 条分流规则；需重新连接”，可展开原始 JSON 差异。运行中的配置和草稿清楚分开。撤销草稿和恢复上一份配置是两个不同动作。

“辅助编写”首先由表单、说明、默认值和校验实现，不要求 AI 账号或网络。自然语言生成规则可后续添加，也必须经过同一套校验与预览。

## 8. 配置所有权和订阅更新

**客户端管理的配置**：存储订阅、节点和用户设置；生成的 JSON 是运行产物，不要求用户编辑它。订阅更新仅更新该来源的节点，不覆盖用户 DNS、分流和收藏。

**用户自有完整配置**：保留原文和未知字段，支持查看、外部编辑、校验和应用。基础表单不能无损表达时不尝试往返改写。可以另外提取节点生成一份独立的客户端管理配置，保留原文件。

更新流程：下载 → 解析 → 展示/记录新增、移除、变更 → 校验候选配置 → 应用。下载/解析/校验失败保留旧订阅与旧配置。首次更新默认每日检查；实际间隔可调整，服务商提示可作为建议。

后台更新先缓存结果；若改变运行配置且需要重启，默认提示待应用，避免突然打断连接。用户可另行启用自动应用并看到重启影响。节点被移除或组变空时不能留下无效引用；按明确的备用规则处理并通知。已连接时短期保留旧节点直到完成替代配置应用。

节点身份优先利用稳定的来源标识，缺失时根据协议、端点及身份参数生成内部 ID；与显示名称分离，不承诺服务商完全变更参数后还能自动识别为同一节点。

## 9. 键盘、鼠标和终端约束

| 输入 | 统一语义 |
|---|---|
| 方向键 / j k | 列表移动，j/k 仅在非文本输入状态生效 |
| Tab / Shift-Tab | 当前页面的焦点区域循环 |
| Enter | 按钮执行；列表打开操作/详情，不隐式改变网络 |
| Esc | 关闭当前弹窗、退出搜索或返回上一层，不断开代理 |
| / | 当前列表搜索 |
| : | 可搜索的操作菜单，也可通过可点击按钮打开 |
| ? | 当前页面帮助，显示实际可用动作和按键 |
| q | 退出界面；后台服务继续工作，仅非文本输入状态生效 |
| Ctrl-C | 取消前台任务；空闲主页面退出界面，不停止后台核心 |

断开代理始终有明确“断开”操作。首次退出提示一次“代理将继续运行”，此后不反复确认。支持鼠标点击页签、按钮、列表和滚动；方向键与可见操作足够完成所有核心任务，Vim 按键只是加速方式。

避免把 Ctrl-S、Ctrl-Q、Option 组合键、系统剪贴板读取作为必要路径，降低 macOS、SSH、tmux 和终端设置差异的影响。处理 bracketed paste；粘贴 URL 时不执行其中的快捷键。

支持 >=120 列的双栏布局，80–119 列使用单栏列表与详情页，较矮终端优先保留顶部状态和底部操作。小于 80×24 提供可滚动紧凑视图或清楚的尺寸提示，不裁掉关键按钮。中文宽度、emoji 宽度不一致和颜色能力需有回退；默认不用 Nerd Font 图标。

## 10. 视觉方向

克制、稳定、可读。默认跟随终端底色，用低对比边框和有限语义颜色。青色用于焦点，绿色配“已连接”，黄色配“待应用/待处理”，红色配“失败”；文字和符号保证不依靠颜色也能理解。

只在总览放一个紧凑的流量趋势，不把所有页面做成仪表盘。没有实时数据时明确显示“暂无数据/数据已过期”，不使用看似真实的占位数字。正文、选中项、当前出口和危险动作有不同样式。减少闪烁和非必要动画。

## 11. 状态与错误体验

连接状态：未连接、正在准备、正在连接、已运行且已验证、已运行但未验证、正在断开、失败。API 断连与核心退出是不同事件。

错误消息采用“发生什么 + 保留了什么 + 下一步”：

- 订阅超时：“更新失败，仍保留上次的 48 个节点。重试 / 修改链接。”
- 部分节点不支持：“导入 48 个，跳过 2 个。查看原因。”
- 校验失败：“新设置未生效，当前连接保持原状。返回修改 / 查看详情。”
- 应用失败：“正在尝试恢复上一份配置。”只有验证成功后才显示“已恢复”；恢复失败需保留明确诊断。
- 端口被占用：“代理端口 2080 已被占用。选择其他端口 / 查看详情。”
- SSH 场景 TUN 应用：“这会修改远端机器路由，SSH 可能中断。”只在用户选择该动作时解释影响；实现恢复措施需专门测试，不能承诺绝不掉线。

测速和订阅更新异步进行，可以取消；避免取消之后后台结果仍覆盖新操作。日志列表滚动时暂停跟随，返回底部后恢复。日志/连接历史有容量上限。

## 12. 内部职责与平台差异

TUI → 客户端管理服务 → 订阅解析/配置生成/系统集成；管理服务持有真实状态，TUI 可随时连接和退出。运行态通过适配层调用 sing-box 的管理 API。订阅导入不依赖 Clash/Mihomo 进程，也无需远程转换服务。

优先评估官方 gRPC 管理 API；实现前固定核心版本，验证节点选择、测速、日志、连接统计的实际方法与依赖。若某功能需要 sing-box 自己的 Clash 兼容模块，可由运行适配层处理，不把“选择 API”暴露给普通用户。支持节点 transport=gRPC 不等于支持管理 API。

配置应用：生成候选 → 核心校验 → 保存最后可用版本 → 原子落盘 → 受控应用/重启 → 核心状态与连通性验证 → 失败回滚。原子落盘只能保证文件完整，不能保证重启时连接不中断；界面需表达这一点。

macOS 使用 launchd，Linux 优先 systemd；非 systemd 的 Linux 首版提供仅代理端口与受限的直接运行路径，完善后台服务集成可后续扩展。TUN 和系统 DNS/代理改动需要平台权限适配；普通界面不必长期以 root 运行。具体 helper/service 方案需在实现阶段单独验证。

系统代理只影响遵循该设置的应用，不能保证所有终端工具自动使用；“仅代理端口”页面提供对应 shell 的可复制环境变量示例，进程本身无法替父 shell 修改环境。SSH 端操作展示目标主机名。

## 13. 第一版的范围与验证

第一版应交付完整的首次连接体验：原生 TUI、常见订阅自动识别、来源与节点管理、收藏与搜索、延迟测试、接管方式、基础分流和 DNS、配置校验与回滚、后台运行、连接与日志。

不以支持协议名称的数量宣称兼容性。先明确 URI/Clash/sing-box 输入的支持矩阵，包括 transport、TLS/Reality 和关键参数；不能转换的字段和协议必须报告，不静默弱化。旧项目解析器仅作参考，需要新的样例测试验证。

后续再增加：复杂嵌套规则编辑、全量配置树、远程多机器管理、AI 生成规则、更多服务管理器、主题市场。第一版不强制包含这些功能。

验收标准（设计目标，尚未测量）：

- 从粘贴有效订阅到发起连接不超过三个主要动作，不含安装与系统授权。
- 用户不用阅读 JSON 或学习 Vim 即可完成订阅导入、选节点、修改基础分流。
- 键盘、鼠标均能完成关键路径，SSH 无剪贴板服务也能粘贴导入。
- UI 退出和重新进入不改变连接；断开需明确操作。
- 更新订阅不丢用户规则、收藏和仍存在的节点选择；失败不会清空旧数据。
- 草稿、运行中配置、待更新订阅有清楚的状态区分。
- 核心未运行、API 不通、节点不可达能区分并给出下一步。
- Mac 与 Linux 的 TUN 启停、DNS 恢复、后台重连和故障回滚用真实系统验证。
- 80×24/120×35、中文/英文、浅色/深色、SSH/tmux 的关键流程经过终端测试。
- 常见交互响应目标 <100 ms（不含网络操作）；长任务不冻结界面，基准与硬件须在测试时记录。

## 14. 待收敛的产品决定

用户已确认：首版覆盖 Mac 本机 + Linux 本机及 SSH；英文默认，可切换中文。

接管和分流的默认建议已写进草案，可通过评审调整。命名、具体快捷键小幅调整、实现语言、解析器选型和存储格式由工程验证收敛，不要求用户先理解这些技术细节。

下一阶段建议先制作可键盘操作的原生 TUI 原型，用虚构节点走通首次导入、节点页和配置草稿应用；这能验证真实终端中的焦点和布局，再接入核心。当前仅为建议，尚未开始实现。
